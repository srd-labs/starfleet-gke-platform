# Cloud Logging and BigQuery Validation

## Overview

This document describes the centralized logging and BigQuery log analytics implementation for the Starfleet GKE Platform Lab.

Application logs generated by the Navigation and Communications services are collected from both GKE clusters by Google Cloud Logging. A project-level Logging sink exports the selected application logs into a partitioned BigQuery table for centralized SQL analysis.

```text
Navigation / Communications
        ↓
Alpha and Delta GKE Clusters
        ↓
Container stdout / stderr
        ↓
Google Cloud Logging
        ↓
starfleet-gke-app-logs
        ↓
BigQuery: starfleet_gke_logs
        ↓
SQL Analytics
```

## GKE Application Log Validation

Application logging was first verified directly from Kubernetes using `kubectl logs`.

Navigation:

```bash
kubectl logs -l app=starfleet-navigation-service --tail=20
```

Communications:

```bash
kubectl logs -l app=starfleet-communications-service --tail=20
```

Both applications produced Werkzeug access logs containing successful `/health` requests with HTTP status `200`.

## Cloud Logging Validation

Cloud Logging ingestion was verified using `gcloud logging read`.

Navigation example:

```bash
gcloud logging read \
'resource.type="k8s_container"
resource.labels.cluster_name="enterprise-gke-delta"
labels.k8s-pod/app="starfleet-navigation-service"' \
--project=starfleet-gke-platform-lab \
--limit=20 \
--format="table(timestamp,resource.labels.pod_name,textPayload)"
```

Communications example:

```bash
gcloud logging read \
'resource.type="k8s_container"
resource.labels.cluster_name="enterprise-gke-delta"
labels.k8s-pod/app="starfleet-communications-service"' \
--project=starfleet-gke-platform-lab \
--limit=20 \
--format="table(timestamp,resource.labels.pod_name,textPayload)"
```

The results confirmed that logs from both replicas of both applications were available in Cloud Logging with timestamps, pod names, and application log messages.

## Terraform-Managed BigQuery Export

The centralized log export infrastructure is managed through Terraform.

The implementation creates:

- BigQuery dataset `starfleet_gke_logs`
- Project-level Logging sink `starfleet-gke-app-logs`
- BigQuery dataset IAM permission for the Logging sink writer identity
- Timestamp-partitioned BigQuery log tables

The Logging sink is filtered so only the two Starfleet application workloads are exported:

```text
resource.type="k8s_container"
(
  labels.k8s-pod/app="starfleet-navigation-service"
  OR
  labels.k8s-pod/app="starfleet-communications-service"
)
```

Terraform plan confirmed:

```text
Plan: 3 to add, 0 to change, 0 to destroy.
```

## Logging Sink Validation

The Logging sink was verified with:

```bash
gcloud logging sinks describe starfleet-gke-app-logs \
  --project=starfleet-gke-platform-lab
```

Validated configuration:

```text
name: starfleet-gke-app-logs
destination: bigquery.googleapis.com/projects/starfleet-gke-platform-lab/datasets/starfleet_gke_logs
usePartitionedTables: true
usesTimestampColumnPartitioning: true
```

A dedicated Cloud Logging writer identity was also generated and granted access to the BigQuery dataset through Terraform.

## BigQuery Table Validation

The dataset was inspected using:

```bash
bq ls \
  --project_id=starfleet-gke-platform-lab \
  starfleet_gke_logs
```

Result:

```text
tableId   Type    Time Partitioning
--------  ------  ----------------------
stderr    TABLE   DAY (field: timestamp)
```

The `stderr` table contains the Flask/Werkzeug application access logs exported by Cloud Logging.

## SQL Query Organization

Reusable SQL queries are stored separately under:

```text
docs/bigquery/queries/
```

Queries can be executed directly with the `bq` CLI. Example:

```bash
bq query \
  --project_id=starfleet-gke-platform-lab \
  --use_legacy_sql=false \
  < docs/bigquery/queries/log-count-by-cluster.sql
```

## Log Count by Cluster

The `log-count-by-cluster.sql` query validates that application logs from both GKE clusters are centralized in BigQuery.

Observed result:

```text
+----------------------+-----------+
| cluster_name         | log_count |
+----------------------+-----------+
| enterprise-gke-delta |       660 |
| enterprise-gke-alpha |       593 |
+----------------------+-----------+
```

This demonstrates that both Alpha and Delta are contributing logs to the centralized dataset.

## Log Count by Service

The `log-count-by-service.sql` query validates that both Starfleet applications are represented in BigQuery.

Observed result:

```text
+----------------+-----------+
| service        | log_count |
+----------------+-----------+
| navigation     |       682 |
| communications |       678 |
+----------------+-----------+
```

This confirms centralized log collection for both Navigation and Communications.

## Log Count by Cluster and Service

The `log-count-by-cluster-service.sql` query provides the strongest end-to-end validation by grouping logs across both dimensions.

Observed result:

```text
+----------------------+----------------+-----------+
| cluster_name         | service        | log_count |
+----------------------+----------------+-----------+
| enterprise-gke-alpha | communications |       355 |
| enterprise-gke-alpha | navigation     |       345 |
| enterprise-gke-delta | communications |       376 |
| enterprise-gke-delta | navigation     |       391 |
+----------------------+----------------+-----------+
```

This confirms all four expected workload combinations are represented in the centralized logging platform:

```text
Alpha → Navigation
Alpha → Communications
Delta → Navigation
Delta → Communications
```

## Validation Summary

The implementation successfully demonstrates centralized application logging across the multi-cluster GKE platform. Both Starfleet services running in both GKE clusters send container logs to Cloud Logging. A Terraform-managed Logging sink exports the selected workload logs to a partitioned BigQuery dataset, where reusable SQL queries provide centralized analysis by cluster and application.

The validated path is:

```text
GKE Applications
      ↓
Cloud Logging
      ↓
Logging Sink
      ↓
BigQuery
      ↓
SQL Analytics
```

This completes the Cloud Logging and BigQuery log analytics portion of the Starfleet GKE Platform Lab.
